# Google Play Console setup (manual)

Create these products in Play Console for `com.daterplat.app` before end-to-end testing:

## Subscription — Dater Premium
- Product ID: `dater_premium`
- Base plans: **`week-one`**, **`month`**, **`three-month`** (mapped in migration 039)

| Admin `pack_code` | Play product | Base plan |
|-------------------|--------------|-----------|
| `PREMIUM_WEEK` | `dater_premium` | `week-one` |
| `PREMIUM_MONTH` | `dater_premium` | `month` |
| `PREMIUM_THREE_MONTHS` | `dater_premium` | `three-month` |

## Consumables (managed, consumable flag ON)
- `boost_3`, `boost_6`, `boost_15`
- `comments_2`, `comments_5`, `comments_15`
- `chat_unlock_single`

## Service account
1. Link GCP project in Play Console → API access
2. Create service account with Android Publisher API access
3. Grant Play Console user permissions (view financial data, manage orders)
4. Set in backend `.env`:

```env
GOOGLE_PLAY_PACKAGE_NAME=com.daterplat.app
GOOGLE_PLAY_SERVICE_ACCOUNT_PATH=./secrets/google-play-service-account.json
BILLING_DEV_MODE=false
```

**Important:** Do NOT paste multiline JSON into `.env` — dotenv truncates at the first
newline and billing will fail with `PLAY_NOT_CONFIGURED`. Either:

- Put the JSON file at `backend/secrets/google-play-service-account.json` (gitignored), or
- Use a single-line minified `GOOGLE_PLAY_SERVICE_ACCOUNT_JSON={"type":"service_account",...}`

Verify on the server after deploy:

```bash
npm run verify:play-config
```

## RTDN (Real-time developer notifications)
1. Create Pub/Sub topic `play-rtdn` in GCP
2. Play Console → Monetization → Real-time developer notifications → link topic
3. Grant `pubsub.publisher` to `google-play-developer-notifications@system.gserviceaccount.com`
4. Create **push subscription** → `https://<api-host>/api/v1/billing/google-webhook`
5. Set in backend `.env`:

```env
GOOGLE_PLAY_RTDN_AUDIENCE=https://<api-host>/api/v1/billing/google-webhook
```

The backend verifies Pub/Sub push JWTs via `google-auth-library` (`pubsubAuth.middleware.js`).

## License testers
Add tester Google accounts in Play Console → Setup → License testing (accelerated renewals ~5 min per “month”).

## Internal testing
Upload a signed release AAB to **Internal testing** and install from the Play Store link (not sideloaded debug APK).

Confirm DaterAdmin → Products shows `dater_premium` + correct base plan IDs after `npm run migrate`.

Verify public API (each premium row must include `googlePlayBasePlanId`):

```bash
curl -s http://localhost:3000/api/v1/config/products | jq '.data.premium[] | {packCode, googlePlayProductId, googlePlayBasePlanId}'
npm run verify:products-catalog
```

Expected premium rows:

```json
{"packCode":"PREMIUM_WEEK","googlePlayProductId":"dater_premium","googlePlayBasePlanId":"week-one"}
{"packCode":"PREMIUM_MONTH","googlePlayProductId":"dater_premium","googlePlayBasePlanId":"month"}
{"packCode":"PREMIUM_THREE_MONTHS","googlePlayProductId":"dater_premium","googlePlayBasePlanId":"three-month"}
```

Use active Play base plans only: `week-one`, `month`, `three-month` (not inactive `week`).

## Cron jobs (production)
Schedule on your host (e.g. Railway cron, Cloud Scheduler):

| Schedule | Command |
|----------|---------|
| Every 15 min | `npm run billing:retry-fulfillment` |
| Daily | `npm run billing:reconcile-subscriptions` |

## iOS (future)
Backend tables (`store_purchase_verifications`, `store_subscriptions`, `store_webhook_events`) use `platform = GOOGLE_PLAY | APP_STORE`. iOS will call `POST /api/v1/billing/verify-purchase` with `platform: APP_STORE`.
